# 质检导出骨架设计

## 目标

补齐第一阶段“报告导出”页面的真实数据骨架，让导出页不再展示硬编码数字，而是基于当前数据集的真实规则、资产盘点、问题扫描和人工复核记录生成导出摘要。

## 范围

本次只做“导出骨架”，不生成最终 PDF/Excel 文件，不伪造合规结论，不自动补全报告内容。

真实聚合来源限定为：

- 规则抽取结果
- 数据资产盘点结果
- 质检扫描问题
- 人工复核记录
- 已创建导出任务

## 设计

后端新增一个只读导出摘要接口，返回导出页需要的真实统计与分组结果。摘要包含六类交付物：

1. 第三批数据检测报告
2. 不合规问题清单
3. 可能合规清单
4. 需人工复核清单
5. 人工复核记录
6. 规则命中统计

其中：

- “不合规问题清单”来自已确认问题
- “可能合规清单”来自已驳回问题
- “需人工复核清单”来自待复核、AI 评审、争议状态问题
- “人工复核记录”来自真实 review records
- “规则命中统计”来自扫描问题按 rule_id 分组后的命中次数
- “第三批数据检测报告”展示覆盖范围摘要，不伪造报告正文

前端沿用现有 `default-assets.ts` / `default-rules.ts` 的加载方式，新增导出摘要 loader，把后端 snake_case 结果映射为导出页使用的 camelCase 结构。`QualityShell` 的导出视图只消费这个摘要，替换目前写死的统计卡片和导出预览表。

## 错误处理

- 后端沿用现有质量接口风格，数据集路径不存在时返回 `404`
- 前端 loader 拉取失败时回退为现有原型视图，保证页面仍可打开
- 导出页只展示已有真实证据，不把缺失数据解释为“通过”

## 测试

- 后端：先写导出摘要聚合测试，再补 API 测试
- 前端：先写导出页使用真实摘要渲染的测试，再改组件
- 完成后跑后端测试、前端相关单测与 `lint`
